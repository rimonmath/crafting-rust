# অধ্যায় ১: কেন রাস্ট? আমরা কীভাবে রাস্ট শিখব

## আপনি কী শিখবেন
- সফটওয়্যার ইঞ্জিনিয়ারিংয়ের ঐতিহাসিক সংকট: স্পিড বনাম মেমরি সেফটি।
- কেন বিশ্বের শীর্ষ টেক কোম্পানিগুলো গুরুত্বপূর্ণ সিস্টেম কম্পোনেন্ট রাস্টে রূপান্তর করছে।
- কীভাবে কোনো গার্বেজ কালেক্টর (GC) ছাড়া শুধুমাত্র কম্পাইল টাইমে নাল পয়েন্টার ও ডেটা রেসের মতো মারাত্মক বাগ দূর করা সম্ভব।
- অবাস্তব সিনট্যাক্স মুখস্থ না করে MiniStore প্রজেক্টের বাস্তব চাহিদার মাধ্যমে ধাপে ধাপে রাস্ট শেখার কৌশল।

---

## আমাদের কেন এটি প্রয়োজন?
একজন অভিজ্ঞ সফটওয়্যার প্রকৌশলী হিসেবে আপনি ইতিমধ্যেই Python, Java, Go, C++ বা TypeScript-এর মতো ভাষায় কাজ করেছেন। কিন্তু প্রচলিত প্রতিটি প্রোগ্রামিং ভাষাতেই কোনো না কোনো বড় আপস (Trade-off) করতে হয়:

1. **গার্বেজ কালেক্টেড ভাষা (Go, Java, C#, Python, JS)**: ডেভেলপমেন্টের গতি বেশি এবং মেমরি নিয়ে ভাবতে হয় না, কিন্তু এর বিনিময়ে বহন করতে হয় GC পজ (Garbage Collection latency), ভারী মেমরি ফুটপ্রিন্ট এবং আনপ্রেডিক্টেবল রিসোর্স ম্যানেজমেন্টের মতো সমস্যা।
2. **ম্যানুয়াল মেমরি ভাষা (C, C++)**: চরম গতি এবং হার্ডওয়্যারের সর্বোচ্চ নিয়ন্ত্রণ পাওয়া যায়, তবে সামান্য ভুলে তৈরি হয় Use-after-free, Double-free, Buffer Overflow ও Data Race-এর মতো ক্যাটাস্ট্রফিক মেমরি করাপশন।

মাইক্রোসফট এবং গুগলের গবেষণা অনুযায়ী, তাদের সফটওয়্যারে পাওয়া মোট ক্রিটিক্যাল সিকিউরিটি ভালনারেবিলিটির প্রায় **৭০% মেমরি সেফটি জনিত ভুলের কারণে** ঘটে। রাস্ট এই বহু পুরনো সমস্যার এক বৈপ্লবিক সমাধান: **কোনো গার্বেজ কালেক্টর ছাড়াই C/C++ এর সমকক্ষ গতি এবং শতভাগ মেমরি সেফটির নিশ্চয়তা।**

---

## সমস্যাটি কী?
অন্যান্য ভাষায় সাধারণ মিউটেশন বা রেফারেন্সের কারণে কীভাবে নিরবে বাগ তৈরি হয় তা লক্ষ্য করুন:

```typescript
// TypeScript / JavaScript
function applyDiscount(cart: Cart) {
    cart.total -= 10; // মূল কার্টের স্টেট সরাসরি বদলে যাচ্ছে!
}
```

C++ এ কোনো অবজেক্ট ফ্রি হওয়ার পর তার রেফারেন্স রয়ে গেলে তৈরি হয় Dangling Pointer:

```cpp
// C++ Dangling Pointer
std::vector<int> numbers = {1, 2, 3};
int& ref = numbers[0];
numbers.push_back(4); // ভেক্টর রি-অ্যালোকেট হলে পুরাতন মেমরি মুছে যায়!
// 'ref' এখন একটি বাতিল মেমরি অ্যাড্রেসকে নির্দেশ করছে—আনডিফাইন্ড বিহেভিয়ার!
```

এই ধরণের সূক্ষ্ম বাগগুলো সাধারণ কোড রিভিউ বা ইউনিট টেস্টে সহজে ধরা পড়ে না; প্রোডাকশনে হাই ট্রাফিকের সময় ক্র্যাশ ঘটিয়ে বিপর্যয় তৈরি করে।

## রাস্টের সমাধান (Rust Concept)
রাস্ট ম্যাথমেটিক্যাল অ্যাফাইন টাইপ সিস্টেম এবং **Ownership & Borrowing** মডেলের মাধ্যমে এই সমস্যার স্থায়ী সমাধান করে:

1. **Zero-Cost Abstractions**: রাস্টের হাই-লেভেল অ্যাবস্ট্রাকশনগুলো কম্পাইল হয়ে হ্যান্ড-টিউনড সি কোডের মতোই মেশিন কোডে পরিণত হয়। অতিরিক্ত কোনো রানটাইম পেনাল্টি দিতে হয় না।
2. **কম্পাইল-টাইম মেমরি ম্যানেজমেন্ট**: ওনার ভ্যারিয়েবলের স্কোপ শেষ হওয়া মাত্রই মেমরি তৎক্ষণাৎ মুক্ত হয়ে যায়। কোনো ব্যাকগ্রাউন্ড GC থ্রেডের প্রয়োজন নেই।
3. **নাল পয়েন্টার মুক্ত (No Null)**: রাস্টে `null` বা `nil` বলে কিছু নেই। কোনো মান অনুপস্থিত থাকতে পারলে তাকে `Option<T>` টাইপ দিয়ে নিশ্চিতভাবে হ্যান্ডেল করতে হয়।
4. **ফিয়ারলেস কনকারেন্সি (Fearless Concurrency)**: মাল্টিথ্রেডেড কোড যদি কম্পাইল হয়, তবে রানটাইমে কোনো Data Race থাকা গাণিতিকভাবে অসম্ভব।

## অন্যান্য ভাষা থেকে আসলে যা জানা দরকার

| বৈশিষ্ট্য | Go / Java / C# / Python | C++ | Rust |
| :--- | :--- | :--- | :--- |
| **মেমরি ক্লিনআপ** | গার্বেজ কালেক্টর (GC) | RAII + ম্যানুয়াল `delete` | কম্পাইল-টাইম ওনারশিপ (Drop) |
| **নাল ভ্যালু** | `null` / `nil` / `None` | `nullptr` | `Option<T>` (টাইপ-সেফ) |
| **পয়েন্টার / রেফারেন্স** | রেফারেন্স (GC নিয়ন্ত্রিত) | র পয়েন্টার (Dangling হতে পারে) | Borrowing (`&` এবং `&mut`) কম্পাইলার কর্তৃক যাচাইকৃত |
| **কনকারেন্সি সেফটি** | রানটাইম রেস ডিটেক্টর | ম্যানুয়াল লক / অ্যাটমিক | কম্পাইল-টাইম থ্রেড সেফটি (`Send` / `Sync`) |

## ছোট উদাহরণ
রাস্টে যেকোনো ভ্যারিয়েবল ডিফল্টভাবে ইমিউটেবল (অপরিবর্তনশীল):

```rust
fn main() {
    let store_name = "MiniStore Central";
    println!("স্বাগতম: {}", store_name);

    // store_name = "MiniStore Branch";
    // ^ উপরের লাইনটি কম্পাইল হবে না!
    // রাস্টে ভ্যারিয়েবল ডিফল্টভাবে অপরিবর্তনশীল।
}
```

অন্যান্য ভাষায় ভ্যারিয়েবল ডিফল্টভাবে পরিবর্তনশীল হলেও রাস্টে শুরুতেই সবকিছু ইমিউটেবল রাখা হয়, যাতে অপ্রত্যাশিত স্টেট পরিবর্তনের সম্ভাবনা গোড়াতেই বন্ধ হয়।

## MiniStore-এ প্রয়োগ
এই বইয়ের মূল উদ্দেশ্য শুধু সিনট্যাক্স শেখা নয়, একটি প্রোডাকশন-গ্রেড ই-কমার্স ইঞ্জিন **MiniStore** তৈরি করা।

> [!TIP]
> **আমাদের ইঞ্জিনিয়ারিং লক্ষ্য:** এই বইয়ে আমরা এমন একটি MiniStore ইঞ্জিন তৈরি করব, যার ফাইনাল অপ্টিমাইজড রিলিজ বিল্ড সাইজ হবে **৫ মেগাবাইটেরও কম (মাত্র প্রায় ৪.৬ মেগাবাইট!)**—কোনো ভারী ভার্চুয়াল মেশিন, গার্বেজ কালেক্টর বা এক্সটার্নাল রানটাইম নির্ভরতা ছাড়াই।

আমরা প্রতিটি কনসেপ্ট কোনো তাত্ত্বিক আলোচনার বদলে MiniStore-এর ইঞ্জিনিয়ারিং সমস্যা সমাধান করতে করতে শিখব:
- ইনভেন্টরি আইটেমের ডাটা মডেল তৈরি → **Structs** এবং প্রিমাক টাইপস।
- স্টক থাকা অবস্থায় যেন একাধিক অর্ডার একই সাথে ভুল স্টেট তৈরি না করতে পারে → **Ownership** ও **Borrowing**।
- পণ্যের স্টক শেষ হয়ে যাওয়া বা ডিসকাউন্ট হ্যান্ডেল করা → **Enums** ও **Option/Result**।
- হাই-পারফরম্যান্স ওয়েব এপিআই উন্মুক্ত করা → **Axum** এবং **Async Rust**।

## কোড
আমাদের MiniStore ডোমেইন মডেলের একটি প্রাথমিক ঝলক:

```rust
// MiniStore ডোমেইন মডেলের প্রাথমিক রূপ
struct Product {
    id: u64,
    name: String,
    price_cents: u32,
    in_stock: bool,
}

fn main() {
    let item = Product {
        id: 101,
        name: String::from("Rust Engineering Guide"),
        price_cents: 2999, // ফ্লোটিং পয়েন্টের ভগ্নাংশের ভুল এড়াতে সেন্ট হিসেবে রাখা
        in_stock: true,
    };

    println!("MiniStore পণ্য #{}: {}", item.id, item.name);
    println!("মূল্য: ${:.2}", item.price_cents as f64 / 100.0);
    println!("স্টকে আছে: {}", if item.in_stock { "হ্যাঁ" } else { "না" });
}
```

---

## কোডটি বুঝে নেওয়া যাক
- `struct Product`: একটি কাস্টম ডাটা মডেল যার সুনির্দিষ্ট টাইপ রয়েছে।
- `u64` ও `u32`: ৬৪-বিট এবং ৩২-বিটের আনসাইন্ড ইন্টিজার। রাস্টে মেমরি সাইজ সবসময় সুনির্দিষ্ট।
- `String::from(...)`: হিপে সংরক্ষিত ওনারশিপ থাকা স্ট্রিং।
- `price_cents: u32`: ফ্লোটিং পয়েন্টের রাউন্ডিং সমস্যা এড়াতে ই-কমার্সে টাকাকে পয়সা বা সেন্ট আকারে ইন্টিজারে রাখা সেরা অভ্যাস।

## সাধারণ ভুলসমূহ

### ১. কম্পাইলারের সাথে লড়াই করা
শুরুতেই অনেকে রাস্ট কম্পাইলারের স্ট্রিক্ট নিয়ম দেখে ভয় পান। তবে মনে রাখবেন, `rustc` আসলে একজন অত্যন্ত অভিজ্ঞ সিনিয়র ইঞ্জিনিয়ারের মতো কাজ করে, যে কোড রান করার আগেই সকল সম্ভাব্য মেমরি ও কনকারেন্সি বাগ ধরিয়ে দেয়।

### ২. সবকিছুকে রেফারেন্স বা পয়েন্টার মনে করা
Java বা Python-এ প্রিমিটিভ ছাড়া সব অবজেক্টই রেফারেন্স। রাস্টে ডিফল্টভাবে সব ভ্যালু স্ট্যাকে (Stack) সংরক্ষিত থাকে, যদি না আপনি ইচ্ছাকৃতভাবে হিপে পাঠান।

## কম্পাইলার এরর ও ডায়াগনস্টিক
আমরা যদি কোনো ইমিউটেবল স্ট্রাক্ট পরিবর্তন করতে যাই:

```rust
fn main() {
    let item = Product {
        id: 101,
        name: String::from("Rust Guide"),
        price_cents: 2999,
        in_stock: true,
    };

    item.in_stock = false; // এরর!
}
```

কম্পাইলার তৎক্ষণাৎ কারণ এবং সমাধান স্পষ্টভাবে দেখিয়ে দেবে:

```text

   |

   |         ---- help: consider changing this to be mutable: `mut item`
```

- কোনো গার্বেজ কালেক্টর ছাড়াই রাস্ট কীভাবে C/C++ এর গতি এবং শতভাগ মেমরি সেফটি নিশ্চিত করে।
- ইমিউটেবিলিটি কেন বাগ-মুক্ত সফটওয়্যার রচনায় অত্যন্ত গুরুত্বপূর্ণ।
- MiniStore প্রজেক্টের মাধ্যমে কীভাবে আমরা পুরো কোর্সটি সম্পন্ন করব।

## পরবর্তী অধ্যায়ে কী থাকছে
**অধ্যায় ২: রাস্ট দিয়ে শুরু করা**-তে আমরা অফিসিয়াল রাস্ট টুলচেন (`rustup`, `rustc`, `cargo`) সেটআপ করব, MiniStore কার্গো প্রজেক্ট ইনিশিয়ালাইজ করব এবং প্রথম রানযোগ্য বাইনারি তৈরি করব।
