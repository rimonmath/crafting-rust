# ২৬. আনসেফ রাস্ট ও নিরাপদ অ্যাবস্ট্রাকশন (Unsafe Rust & Safe Abstractions)

## আপনি যা শিখবেন

- **আনসেফ রাস্ট (Unsafe Rust)** আসলে কী (এবং প্রচলিত ভুল ধারণা: আনসেফ ব্লকে কিন্তু ধারক বা টাইপ চেকার বন্ধ হয় না!)।
- আনসেফ রাস্টের **৫টি বিশেষ ক্ষমতা (5 Superpowers)** যা নিরাপদ রাস্টে নিষিদ্ধ।
- **নিরাপদ রেফারেন্স (`&T`, `&mut T`)** এবং **র পয়েন্টার (`*const T`, `*mut T`)**-এর মধ্যকার কাঠামোগত পার্থক্য।
- **`std::alloc` (`alloc`, `realloc`, `dealloc`, `Layout`)** ব্যবহার করে সরাসরি হিপ মেমরি বরাদ্দ, আকার পরিবর্তন ও খালাস করা।
- রাস্টের সবচেয়ে মৌলিক দর্শন: **আনসেফ প্রিমিতিভের ওপর ১০০% নিরাপদ অ্যাবস্ট্রাকশন (Safe Abstraction) তৈরি করা**।
- রাস্ট স্ট্যান্ডার্ড লাইব্রেরি কীভাবে内部 আনসেফ কোড ব্যবহার করেও বাইরের বিশ্বকে সম্পূর্ণ মেমরি-নিরাপদ এপিআই উপহার দেয় (`Vec`, `String`, `Box`, `Arc`)।
- **ফরেন ফাংশন ইন্টারফেস (Foreign Function Interface - FFI)**: সি স্ট্যান্ডার্ড লাইব্রেরি কল করা (`unsafe extern "C"`) এবং সি-কম্প্যাটিবল ফাংশন এক্সপোর্ট করা (`#[unsafe(no_mangle)]`)।
- কোডে সম্ভাব্য আনডিফাইন্ড বিহেভিয়ার (Undefined Behavior - UB) রোধে **`// SAFETY:`** ডকুমেন্টিং কনভেনশন।

## আমাদের আনসেফ রাস্ট কেন প্রয়োজন?

রাস্টের প্রধান গৌরব হলো কোনো গার্বেজ কালেক্টর ছাড়াই কম্পাইল টাইমে মেমরি সুরক্ষা নিশ্চিত করা। ধারক চেকার (Borrow Checker) নিশ্চিত করে যে কোডে কোনো ড্যাংলিং পয়েন্টার, ডাবল ফ্রি বা ডাটা রেস থাকবে না।

কিন্তু কম্পিউটার হার্ডওয়্যারের বাস্তব জগতটি মূলত অরক্ষিত:
১. **লো-লেভেল হার্ডওয়্যার ও অপারেটিং সিস্টেম**: সিপিইউ, ডিভাইস ড্রাইভার এবং কার্নেল মেমরির কাঁচা অ্যাড্রেস (Raw Addresses), রেজিস্টার এবং ডিএমএ বাফার দিয়ে কাজ করে।
২. **সি ভাষার সাথে সংযোগ (FFI)**: অপারেটিং সিস্টেমের মূল এপিআইগুলো (Linux POSIX, Windows Win32, macOS) এবং ঐতিহ্যবাহী এন্টারপ্রাইজ সিস্টেমগুলো সিতে লেখা। সি ভাষায় কোনো ধারক চেকার বা লাইফটাইম নেই; সেখানে সব কাজ চলে র পয়েন্টার দিয়ে।
৩. **মৌলিক ডাটা স্ট্রাকচার নির্মাণ**: ডাবল-লিঙ্কড লিস্ট, রিং বাফার, কাস্টম মেমরি পুল এবং এমনকি খোদ রাস্টের নিজস্ব `Vec<T>`, `String` কিংবা `HashMap<K, V>` তৈরি করতে গেলে কম্পাইলারের কঠোর "একটি মিউটেবল রেফারেন্স" নিয়ম অতিক্রম করতে হয়।

```
+--------------------------------------------------------------+
|                    নিরাপদ রাস্ট (Safe Rust - ৯৯% কোড)        |
|   - ওনারশিপ ও লাইফটাইম কম্পাইল টাইমে নিশ্চিত                |
|   - কোনো ডাটা রেস বা ড্যাংলিং পয়েন্টার নেই                   |
+--------------------------------------------------------------+
                               |
                               | যার ওপর দাঁড়িয়ে আছে
                               v
+--------------------------------------------------------------+
|            নিরাপদ অ্যাবস্ট্রাকশন প্রাচীর (Safe Abstraction)   |
+--------------------------------------------------------------+
                               |
                               | অভ্যন্তরীণ বাস্তবায়ন
                               v
+--------------------------------------------------------------+
|                    আনসেফ রাস্ট (Unsafe Rust - ১% কোড)       |
|   - র পয়েন্টার (*const T, *mut T)                            |
|   - std::alloc দিয়ে সরাসরি মেমরি ম্যানেজমেন্ট               |
|   - ফরেন ফাংশন ইন্টারফেস (FFI - extern "C")                 |
+--------------------------------------------------------------+
```

যদি রাস্টে কোনো আনসেফ সুযোগ না থাকত, তবে ডেভেলপাররা বাধ্য হয়ে অপারেটিং সিস্টেম ও উচ্চগতির সিস্টেমগুলো সি বা সি++ এ লিখতেন। আনসেফ রাস্টের মাধ্যমে প্রোগ্রামার কম্পাইলারকে বলেন: **"আমাকে বিশ্বাস করো; আমি নিজে সেই নিরাপত্তা শর্তগুলো যাচাই করেছি যা তুমি স্বয়ংক্রিয়ভাবে প্রমাণ করতে পারছ না।"**

---

## আনসেফ রাস্টের ৫টি বিশেষ ক্ষমতা

একটি `unsafe { ... }` ব্লকের অভ্যন্তরে আপনি ঠিক ৫টি কাজ করার সুযোগ পান যা সাধারণ রাস্টে অসম্ভব:

১. **র পয়েন্টার ডিরেফারেন্স করা** (`*const T` এবং `*mut T`)। 2. **কোনো আনসেফ ফাংশন বা মেথড কল করা** (যেমন সি ভাষার FFI ফাংশন)। 3. **কোনো আনসেফ ট্রেইট ইমপ্লিমেন্ট করা** (যেমন `Send` এবং `Sync`)। 4. **মিউটেবল স্ট্যাটিক ভ্যারিয়েবল মিউটেট করা** বা অ্যাক্সেস করা। 5. **`union`-এর ফিল্ড অ্যাক্সেস করা**।

> [!NOTE]
> `unsafe` কিওয়ার্ড ধারক চেকার বা টাইপ চেকারকে বন্ধ করে না! আনসেফ ব্লকের ভেতরেও সব লাইফটাইম ও টাইপ যাচাই আগের মতোই কাজ করে। শুধু ওপরের ৫টি নির্দিষ্ট ক্ষমতা উন্মুক্ত হয়।

## র পয়েন্টার বনাম নিরাপদ রেফারেন্স

নিরাপদ রাস্টে আমরা রেফারেন্স ব্যবহার করি: `&T` (শেয়ার্ড) এবং `&mut T` (একক মিউটেবল)।
আনসেফ রাস্টে আসে **র পয়েন্টার (Raw Pointers)**: `*const T` এবং `*mut T`।

| বৈশিষ্ট্য               | নিরাপদ রেফারেন্স (`&T`, `&mut T`)    | র পয়েন্টার (`*const T`, `*mut T`)              |
| :---------------------- | :----------------------------------- | :--------------------------------------------- |
| **নাল ভ্যালু**          | কখনো নাল হতে পারে না                 | নাল হতে পারে (`std::ptr::null()`)              |
| **বৈধতা**               | সবসময় বৈধ ও সক্রিয় মেমরির নির্দেশক  | ড্যাংলিং বা যেকোনো মেমরি অ্যাড্রেস হতে পারে    |
| **অ্যালাইসিং নিয়ম**     | কঠোর: ১টি মিউটেবল অথবা একাধিক রিড    | একই মেমরিতে একাধিক মিউটেবল পয়েন্টার থাকতে পারে |
| **মেমরি অ্যালাইনমেন্ট** | কম্পাইলার স্বয়ংক্রিয়ভাবে নিশ্চিত করে | মিস-অ্যালাইন্ড হতে পারে                        |
| **অটোমেটিক ক্লিনআপ**    | ওনারশিপ ও `Drop` দিয়ে মুক্ত হয়       | কোনো অটো ক্লিনআপ নেই; ম্যানুয়ালি ফ্রি করতে হয়  |
| **তৈরি করা**            | নিরাপদ                               | **সম্পূর্ণ নিরাপদ** (`&val as *const T`)       |
| **ডিরেফারেন্স করা**     | নিরাপদ (`*ref`)                      | **আনসেফ** (`unsafe { *raw_ptr }`)              |

লক্ষ্য করুন: র পয়েন্টার **তৈরি করা** কিন্তু শতভাগ নিরাপদ! কেবল সেই পয়েন্টারের অ্যাড্রেস থেকে ডাটা পড়া বা লেখা (ডিরেফারেন্স) করার সময় `unsafe` ব্লক প্রয়োজন হয়।

```rust
let mut price: u32 = 15000;

// র পয়েন্টার তৈরি করা সম্পূর্ণ নিরাপদ:
let raw_const: *const u32 = &price;
let raw_mut: *mut u32 = &mut price;

// কিন্তু পয়েন্টার থেকে ডাটা পড়া বা লেখা আনসেফ:
unsafe {
    println!("Price: {}", *raw_const);
    *raw_mut = 18000;
}
```

## নিরাপদ অ্যাবস্ট্রাকশন তৈরি: `RawBarcodeBuffer`

রাস্ট সিস্টেমস প্রোগ্রামিংয়ের সোনালী নীতি হলো: **যদি কোনো আনসেফ অপারেশনকে একটি নিরাপদ এপিআই-এর ভেতর আবদ্ধ করা সম্ভব হয়, তবে বাইরের কলারকে কখনো `unsafe` লিখতে বাধ্য করবেন না।**

মিনিস্টোরে উচ্চগতির বারকোড স্ক্যানিং এবং মেমরি বাফারিংয়ের জন্য আমরা তৈরি করেছি: [`RawBarcodeBuffer`](ministore/src/unsafe_utils.rs)।

### ১. স্ট্রাকচার ও `NonNull` পয়েন্টার

কাঁচা `*mut u8` ব্যবহার না করে আধুনিক রাস্টে `NonNull<u8>` ব্যবহার করা হয়। এটি কম্পাইলারকে নিশ্চিত করে যে পয়েন্টারটি কখনো নাল হবে না:

```rust
use std::alloc::{alloc, dealloc, realloc, Layout};
use std::ptr::NonNull;

#[derive(Debug)]
pub struct RawBarcodeBuffer {
    ptr: NonNull<u8>,
    capacity: usize,
    len: usize,
}

// SAFETY: RawBarcodeBuffer তার হিপ মেমরির একক মালিক এবং কোনো শেয়ার্ড মিউটেবিলিটি নেই।
unsafe impl Send for RawBarcodeBuffer {}
unsafe impl Sync for RawBarcodeBuffer {}
```

### ২. `std::alloc` দিয়ে মেমরি বরাদ্দ

নিরাপদ রাস্টে `Vec::new` স্বয়ংক্রিয়ভাবে মেমরি নেয়। কিন্তু লো-লেভেলে আমরা সরাসরি গ্লোবাল অ্যালোকোটরের সাথে `Layout` দিয়ে যোগাযোগ করি:

```rust
impl RawBarcodeBuffer {
    pub fn with_capacity(capacity: usize) -> Result<Self, StoreError> {
        let cap = capacity.max(1);
        let layout = Layout::array::<u8>(cap).map_err(|e| StoreError::InvalidPayment {
            reason: format!("Invalid memory layout: {e}"),
        })?;

        // SAFETY: লেআউটের সাইজ শূন্য নয় এবং u8-এর জন্য সঠিক অ্যালাইনমেন্ট রয়েছে।
        let raw_ptr = unsafe { alloc(layout) };
        let ptr = NonNull::new(raw_ptr).ok_or_else(|| StoreError::InvalidPayment {
            reason: "Out of memory: raw heap allocation failed".to_string(),
        })?;

        Ok(Self {
            ptr,
            capacity: cap,
            len: 0,
        })
    }
}
```

### ৩. পয়েন্টার এরিথমেটিক ও ডাটা রাইটিং

বাফারে ডাটা যোগ করতে আমরা সরাসরি মেমরির অফসেট হিসাব করে পয়েন্টারে বাইট রাইট করি:

```rust
pub fn push(&mut self, byte: u8) -> Result<(), StoreError> {
    if self.len >= self.capacity {
        self.grow()?;
    }

    // SAFETY:
    // ১. self.ptr নাল নয় এবং রাইট করার জন্য বৈধ।
    // ২. self.len < self.capacity, তাই অফসেটটি বৈধ সীমার ভেতরে রয়েছে।
    unsafe {
        let dest = self.ptr.as_ptr().add(self.len);
        std::ptr::write(dest, byte);
    }
    self.len += 1;
    Ok(())
}
```

### ৪. `Drop` ট্রেইট দিয়ে মেমরি লিক রোধ (RAII)

যেহেতু আমরা `alloc()` দিয়ে ম্যানুয়ালি মেমরি নিয়েছি, তাই রাস্ট নিজে থেকে এটি মুক্ত করবে না। অবজেক্টের স্কোপ শেষ হলে মেমরি মুক্ত করতে আমরা `Drop` ইমপ্লিমেন্ট করি:

```rust
impl Drop for RawBarcodeBuffer {
    fn drop(&mut self) {
        if self.capacity > 0 {
            let layout = Layout::array::<u8>(self.capacity).expect("Valid layout during drop");
            // SAFETY:
            // ১. self.ptr ঠিক এই লেআউট দিয়েই বরাদ্দ করা হয়েছিল।
            // ২. drop কেবল একবারই রান করে যখন অবজেক্ট ধ্বংস হয়।
            unsafe {
                dealloc(self.ptr.as_ptr(), layout);
            }
        }
    }
}
```

এই RAII মেকানিজমের কারণে বাইরের কোনো ডেভেলপারকে কখনোই সি ভাষার মতো `free()` কল করার চিন্তা করতে হয় না!

## ফরেন ফাংশন ইন্টারফেস (Foreign Function Interface - FFI)

রাস্ট খুব সহজে সি লাইব্রেরির কোড কল করতে পারে এবং অন্য ল্যাঙ্গুয়েজের (Python, Go, Node.js) কাছে নিজের ফাংশন উন্মুক্ত করতে পারে।

### ১. সি স্ট্যান্ডার্ড লাইব্রেরি কল করা (`unsafe extern "C"`)

রাস্ট ২০২৪ এডিশনে এক্সটার্নাল সি ফাংশন ডিক্লেয়ার করার সময় `unsafe extern "C"` লিখতে হয়:

```rust
/// সি স্ট্যান্ডার্ড লাইব্রেরির abs ফাংশন কল করে দুটি মূল্যের পরম পার্থক্য বের করা।
pub fn c_abi_price_diff(price_a: i32, price_b: i32) -> i32 {
    unsafe extern "C" {
        fn abs(x: std::ffi::c_int) -> std::ffi::c_int;
    }
    // SAFETY: abs একটি খাঁটি C ফাংশন যার কোনো ক্ষতিকর সাইড-এফেক্ট নেই।
    unsafe { abs(price_a - price_b) }
}
```

### ২. রাস্ট ফাংশন বহির্বিশ্বের জন্য এক্সপোর্ট করা

সি বা পাইথনে কল করার জন্য রাস্ট ফাংশন এক্সপোর্ট করতে:

- `extern "C"` দিয়ে সি কলিং কনভেনশন নির্ধারণ করি।
- `#[unsafe(no_mangle)]` দিয়ে নিশ্চিত করি যেন কম্পাইলার ফাংশনটির নাম বিকৃত (mangle) না করে।

```rust
/// এক্সটার্নাল সিস্টেমের সাথে সংযুক্ত হওয়ার জন্য সি-কম্প্যাটিবল ফাংশন।
#[unsafe(no_mangle)]
pub extern "C" fn ministore_c_calculate_tax(subtotal_cents: u32, tax_rate_percent: u32) -> u32 {
    (subtotal_cents * tax_rate_percent) / 100
}
```
