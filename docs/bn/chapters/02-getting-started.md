# অধ্যায় ২: রাস্ট দিয়ে শুরু করা

## আপনি কী শিখবেন
- অফিসিয়াল রাস্ট টুলচেন কীভাবে গঠিত: `rustup`, `rustc` এবং `cargo`।
- কীভাবে কার্গো (Cargo) বিল্ড সিস্টেম এবং প্যাকেজ ম্যানেজারের জটিলতা দূর করেছে।
- কার্গো প্রজেক্টের এনাটমি: `Cargo.toml`, `Cargo.lock` এবং `src/` ডিরেক্টরি।
- ডেভেলপার ফিডব্যাক লুপ: কেন `cargo build` এর চেয়ে `cargo check` অনেক দ্রুত কাজ করে।
- আমাদের মূল প্রজেক্ট **MiniStore** ইনিশিয়ালাইজ করা এবং প্রথম টেস্ট রান করা।

---

## আমাদের কেন এটি প্রয়োজন?
বাস্তব সফটওয়্যার ডেভেলপমেন্টে কোড লেখার আগেই একটি নির্ভরযোগ্য ও সামঞ্জস্যপূর্ণ বিল্ড পরিবেশ থাকা আবশ্যক।

C এবং C++ এ একাধিক প্ল্যাটফর্মে কাজ করতে গিয়ে Makefiles, CMake, pkg-config কিংবা vcpkg-এর মতো ভিন্ন ভিন্ন টুলের সমন্বয় করতে হয়। অন্যদিকে Python বা JavaScript ইকোসিস্টেমে অসংখ্য প্রতিযোগী টুল (`pip`, `poetry`, `conda`, `npm`, `yarn`, `pnpm`, `webpack`, `vite`) থাকায় প্রায়শই ডিপেন্ডেন্সি জটিলতা তৈরি হয়।

রাস্ট শুরু থেকেই একটি অল-ইন-ওয়ান সমাধান নিয়ে এসেছে। রাস্ট ইন্সটল করলেই স্বয়ংক্রিয়ভাবে একটি স্ট্যান্ডার্ড বিল্ড টুল, প্যাকেজ ম্যানেজার, ডকুমেন্টেশন জেনারেটর, কোড ফরম্যাটার, লিন্টার এবং টেস্ট হারনেস পাওয়া যায়—যার নাম **Cargo**।

---

## সমস্যাটি কী?
বিভিন্ন ডেভেলপারের কম্পিউটারে কম্পাইলার ভার্সন বা বিল্ড সেটিংসের সূক্ষ্ম পার্থক্যের কারণে আধুনিক সফটওয়্যার টিমগুলোতে প্রায়শই সমস্যা দেখা দেয়:
- *"আমার মেশিনে কাজ করছে, কিন্তু CI/CD সার্ভারে ফেইল করছে।"*
- কোডের ছোট একটি পরিবর্তনের পর পুরো বাইনারি বিল্ড হতে দীর্ঘ সময় লাগা।
- সাধারণ ইউনিট টেস্ট লেখার জন্য আলাদা থার্ড-পার্টি লাইব্রেরি (যেমন JUnit, Jest, PyTest) সেটআপ করার ঝামেলা।

রাস্টের তিন-স্তম্ভের টুলচেন আর্কিটেকচার এই সমস্ত সমস্যা গোড়াতেই দূর করে।

## রাস্টের সমাধান: টুলচেন ত্রয়ী (The Toolchain Trinity)

```
┌─────────────────────────────────────────────────────────┐
│                         rustup                          │
│        (টুলচেন ইন্সটলার, আপডেটার ও ভার্সন ম্যানেজার)    │
└────────────────────────────┬────────────────────────────┘
                             │ ইন্সটল ও আপডেট করে
            ┌────────────────┴────────────────┐
            ▼                                 ▼
┌───────────────────────┐         ┌───────────────────────┐
│         cargo         │         │         rustc         │
│  (প্যাকেজ ম্যানেজার ও  │────────▶│ (কম্পাইলার ব্যাকএন্ড, │
│     বিল্ড অর্কেস্ট্রেটর)│ কল করে  │     LLVM চালিত)       │
└───────────────────────┘         └───────────────────────┘
```

1. **`rustup`**: টুলচেন মাল্টিপ্লেক্সার (Node-এর `nvm` বা Python-এর `pyenv`-এর মতো, তবে রাস্টের অফিসিয়াল)। এটি বিভিন্ন কম্পাইলার ভার্সন (stable, beta, nightly) এবং বিভিন্ন প্ল্যাটফর্মের জন্য ক্রস-কম্পাইলেশন টার্গেট পরিচালনা করে।
2. **`rustc`**: মূল রাস্ট কম্পাইলার। এটি কোড পার্স করে, বরো চেকার নিয়ম নিশ্চিত করে, LLVM ইন্টারমিডিয়েট রিপ্রেজেন্টেশনে রূপান্তর করে এবং নেটিভ মেশিন কোড তৈরি করে। দৈনন্দিন কাজে সরাসরি `rustc` কল করার প্রয়োজন পড়ে না।
3. **`cargo`**: মূল কমান্ড-লাইন টুল যা নিয়ে আমরা কাজের ৯৯% সময় কাটাব। এটি ডিপেন্ডেন্সি ডাউনলোড, প্রজেক্ট বিল্ড, টেস্ট রান এবং ডকুমেন্টেশন তৈরির কাজ স্বয়ংক্রিয়ভাবে করে।

## ছোট উদাহরণ: দ্রুত ফিডব্যাক লুপ

রাস্টে কোড লেখার সময় প্রতিবার ফাইল সেভ করার পর সম্পূর্ণ মেশিন কোড জেনারেট হওয়ার জন্য অপেক্ষা করার কোনো দরকার নেই।

রাস্টের বিশেষ সুবিধা `cargo check`:
```bash
# ফুল বিল্ড: কোড যাচাই করে + মেশিন কোড তৈরি করে ও লিংক করে (তুলনামূলক ধীর)
cargo build

# দ্রুত সিনট্যাক্স ও টাইপ চেক: কোনো বাইনারি ফাইল তৈরি না করেই টাইপ ও ওনারশিপ রুল যাচাই করে (অত্যন্ত দ্রুত)
cargo check
```

অভিজ্ঞ রাস্ট ডেভেলপাররা কোড লেখার সময় সবসময় ব্যাকগ্রাউন্ডে বা টার্মিনালে `cargo check` রান করে রাখেন, যা চোখের পলকে নির্ভুল ফিডব্যাক দেয়।

## MiniStore-এ প্রয়োগ
এখন আমরা আমাদের প্রজেক্ট **MiniStore** ইনিশিয়ালাইজ করব। MiniStore একটি বাইনারি অ্যাপ্লিকেশন হিসেবে শুরু হচ্ছে:

```bash
cargo new ministore --bin
```

এর ফলে একটি পরিষ্কার ডিরেক্টরি কাঠামো তৈরি হয়:
```
ministore/
├── Cargo.toml       # প্রজেক্টের মেটাডাটা ও ডিপেন্ডেন্সি কনফিগারেশন
└── src/
    └── main.rs      # অ্যাপ্লিকেশনের মূল এন্ট্রি পয়েন্ট
```

## কোড

### `ministore/Cargo.toml`
```toml
[package]
name = "ministore"
version = "0.1.0"

# আপাতত কোনো এক্সটার্নাল ডিপেন্ডেন্সি নেই — আমরা আগে পিওর রাস্ট শিখব!
```

```rust
fn main() {
    println!("=== MiniStore ===");

#[cfg(test)]
mod tests {
    #[test]

        assert_eq!(app_name, "MiniStore");
    }
}
```

## কোডটি বুঝে নেওয়া যাক

### ১. `println!` ম্যাক্রো
`println!(...)` লেখার সময় শেষের বিস্ময়বোধক চিহ্ন (`!`) খেয়াল করুন। রাস্টে কোনো নামের শেষে `!` থাকা মানে সেটি সাধারণ ফাংশন নয়, একটি **ম্যাক্রো**।

কেন এটি ফাংশন না হয়ে ম্যাক্রো হলো?
C ভাষায় `printf("%s %d", str)` ফাংশনটি কম্পাইল টাইমে টাইপ যাচাই করে না; ভুল প্যারামিটার দিলে রানটাইমে মেমরি ক্র্যাশ হতে পারে। রাস্টে `println!` একটি কম্পাইল-টাইম ম্যাক্রো হওয়ায় ফরম্যাট স্ট্রিং এবং ভ্যারিয়েবলের টাইপ **কম্পাইল করার মুহূর্তেই** যাচাই করে নেয়।

### ২. বিল্ট-ইন টেস্টিং: `#[cfg(test)]`
- `#[cfg(test)]`: একটি কন্ডিশনাল কম্পাইলেশন অ্যাট্রিবিউট। যখন আপনি `cargo test` চালাবেন, কেবল তখনই কম্পাইলার এই মডিউলটি কম্পাইল করবে। ফলে প্রোডাকশন বাইনারি অপ্রয়োজনীয় টেস্ট কোডে ভারী হয় না।
- `#[test]`: এই ফাংশনটিকে একটি রানযোগ্য টেস্ট হিসেবে চিহ্নিত করে।
- `assert_eq!`: আরেকটি ম্যাক্রো যা দুটি মান সমান কিনা যাচাই করে এবং অসঙ্গতি থাকলে স্পষ্ট বিবরণ দেয়।

## সাধারণ ভুলসমূহ

### ১. `target/` ফোল্ডার গিট-এ কমিট করা
কার্গো যখন কোড কম্পাইল করে, তখন মধ্যবর্তী ফাইল এবং বাইনারিগুলো `target/` ফোল্ডারে জমা হয়। এর আকার শত শত মেগাবাইট হতে পারে। তাই এটি সবসময় `.gitignore`-এ রাখা নিশ্চিত করুন।

### ২. ম্যানুয়ালি `Cargo.lock` এডিট করা
- `Cargo.toml`: এটি ডেভেলপার নিজে লেখেন এবং লাইব্রেরির সেমভার (SemVer) রেঞ্জ নির্ধারণ করেন।
- `Cargo.lock`: এটি কার্গো নিজে তৈরি করে এবং সব ট্রানজিটিভ ডিপেন্ডেন্সির নির্দিষ্ট ক্রিপ্টোগ্রাফিক হ্যাশ সংরক্ষণ করে। এটি কখনোই ম্যানুয়ালি এডিট করবেন না।

## কম্পাইলার এরর ও ডায়াগনস্টিক
আমরা যদি `println!` ম্যাক্রোতে ফরম্যাট স্ট্রিং অনুযায়ী পর্যাপ্ত আর্গুমেন্ট না দিই:

```rust
fn main() {
    let name = "MiniStore";
    println!("Welcome to {}, Version {}", name); // দ্বিতীয় আর্গুমেন্ট অনুপস্থিত!
}
```

কম্পাইলার তাৎক্ষণিকভাবে এটি ধরে ফেলবে:

```text
error: 2 positional arguments in format string, but there is 1 argument
 --> src/main.rs:3:14
  |
3 |     println!("Welcome to {}, Version {}", name);
  |              ^^^^^^^^^^^^^^^^^^^^^^^^^^^  ----
  |              |                            |
  |              |                            this is the 1st argument
  |              positional arguments 1 and 2 are referenced here, but only 1 argument was provided
```

অন্যান্য ভাষায় যা রানটাইম এরর তৈরি করত, রাস্টে তা কোড চলার আগেই কম্পাইলার আটকে দেয়।

## নিজে অনুশীলন করুন
আপনার `ministore/` ডিরেক্টরিতে ঢুকে নিচের কমান্ডগুলো রান করুন:

1. দ্রুত টাইপ যাচাই করুন:
   ```bash
   cargo check
   ```
2. টেস্ট সুইট রান করুন:
   ```bash
   cargo test
   ```
3. অ্যাপ্লিকেশনটি রান করুন:
   ```bash
   cargo run
   ```
4. কোড ফরম্যাটিং চেক করুন:
   ```bash
   cargo fmt -- --check
   ```

- রাস্টের কম্পাইল-টাইম ম্যাক্রো সাধারণ ফাংশনের চেয়ে অনেক বেশি সুরক্ষিত।
