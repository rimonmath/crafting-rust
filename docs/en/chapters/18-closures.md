## Why Do We Need This?

In Chapter 3, we learned how to write standard functions using the `fn` keyword:
```rust
fn is_discount_eligible(subtotal_cents: u32) -> bool {
    subtotal_cents >= 10000
}
```

Standard functions have one critical limitation: **they cannot access local variables from the surrounding environment where they are called.**

Consider this real-world scenario in MiniStore:
A user enters a maximum budget into a search box, and we want to filter the product catalog based on that dynamically entered threshold:

```rust
let max_budget = 10000; // Local variable entered by the user

// We cannot pass a standard function `fn` here because a standard function
// has no way of reading `max_budget` without hardcoding it!
```

### The Solution: Closures
A **closure** is an anonymous function that can be saved in a variable, passed into other functions, and—most importantly—**capture values from the scope in which it is defined**:

```rust
let max_budget = 10000;

// The closure |p| borrows `max_budget` directly from the enclosing scope!
let affordable_products = catalog.find_products(|p| p.price_cents <= max_budget);
```

## Closure Syntax & Type Inference

Closures use vertical pipes (`|...|`) instead of parentheses for their parameter list:

```rust
// 1. Standard function
fn add_one_fn(x: u32) -> u32 { x + 1 }

// 2. Closure with full explicit type annotations
let add_one_v1 = |x: u32| -> u32 { x + 1 };

// 3. Closure with inferred parameter and return types
let add_one_v2 = |x| x + 1;

// 4. Closure with a multi-statement block body
let calculate_tax = |price: u32| {
    let rate = 15;
    (price * rate) / 100
};
```

### Type Locking
Unlike standard functions, closures rarely require type annotations because the compiler infers types from how the closure is first invoked.

However, once Rust infers the types for a closure, **those types are locked**:
```rust
let print_item = |x| println!("{}", x);

print_item(String::from("Keyboard")); // Type locked to `String`
// print_item(101); // COMPILE ERROR: expected `String`, found integer!
```

## How Closures Capture Their Environment

When a closure uses a variable from its enclosing scope, it captures that variable in one of three ways:

### 1. Capturing by Immutable Reference (`&T`)
If the closure only reads the variable, it borrows an immutable reference:
```rust
let store_name = String::from("MiniStore");
let greet = || println!("Welcome to {}", store_name);

greet();
println!("Store: {}", store_name); // OK: store_name was only borrowed immutably
```

### 2. Capturing by Mutable Reference (`&mut T`)
If the closure modifies the captured variable, it borrows a mutable reference:
```rust
let mut total_discount = 0;
let mut record_discount = |amount| {
    total_discount += amount; // Mutates captured variable
};

record_discount(500);
record_discount(1000);
println!("Total discount: ${:.2}", total_discount as f64 / 100.0); // $15.00
```
Notice: The closure variable itself must be declared `let mut` because invoking it mutates internal state.

### 3. Capturing by Value (`move`)
If you want the closure to take full **ownership** of the captured values, prefix the closure with the **`move`** keyword:
```rust
let greeting = String::from("Welcome");
let print_welcome = move || {
    println!("{}", greeting); // `greeting` is MOVED into the closure!
};

print_welcome();
// println!("{}", greeting); // COMPILE ERROR: value borrowed here after move!
```

The `move` keyword is especially vital when returning closures from functions or passing closures to background threads.

## The Three Closure Traits: `FnOnce`, `FnMut`, and `Fn`

Every closure automatically implements one or more of three traits based on how it handles its captured values:

```
          ┌────────────┐
          │   FnOnce   │ (Can be called at least once; might consume captured values)
          └─────▲──────┘
                │
          ┌─────┴──────┐
          │   FnMut    │ (Can be called repeatedly; mutates captured values in place)
          └─────▲──────┘
                │
          ┌─────┴──────┐
          │     Fn     │ (Can be called repeatedly; only borrows captured values immutably)
          └────────────┘
```

### 1. `FnOnce`
- Applies to all closures.
- Can be called at least once.
- If a closure consumes or moves captured values out of its environment (e.g. dropping them or pushing them into an owned collection), it can **only** be called once and only implements `FnOnce`.

### 2. `FnMut`
- Inherits from `FnOnce`.
- Applies to closures that mutate captured values, but do not move them out of scope.
- Can be called multiple times in sequence.

### 3. `Fn`
- Inherits from `FnMut` (and therefore `FnOnce`).
- Applies to closures that only borrow captured values immutably (or capture nothing at all).
- Can be called multiple times concurrently.

## Functions Accepting Closures

To write a function that accepts a closure, use generics bounded by one of the closure traits:

```rust
impl Catalog {
    /// Accepts any closure that takes a `&Product` and returns a `bool`.
    pub fn find_products<P>(&self, predicate: P) -> Vec<&Product>
    where
        P: Fn(&Product) -> bool,
    {
        self.products.values().filter(|p| predicate(p)).collect()
    }
}
```

And for stateful operations, accept `FnMut`:
```rust
impl ShoppingCart {
    /// Accepts a mutable closure allowing the caller to track state across items.
    pub fn apply_custom_discount<F>(&mut self, mut discount_calc: F)
    where
        F: FnMut(&CartItem) -> u32,
    {
        for item in &mut self.items {
            let discount = discount_calc(item);
            item.unit_price_cents = item.unit_price_cents.saturating_sub(discount);
        }
    }
}
```

## Returning Closures: Factory Functions with `move`

In MiniStore, promotion rules frequently depend on runtime parameters (like flash sale percentages or customer loyalty tiers).

We can write **closure factories** that return specialized closures using `impl Fn` and `move`:

```rust
/// Creates a customized percentage discount closure.
pub fn make_percentage_discount(percentage: u32) -> impl Fn(u32) -> u32 {
    move |amount_cents| (amount_cents * percentage) / 100
}

/// Creates a customized threshold discount closure ($20 off orders >= $150).
pub fn make_threshold_discount(min_cents: u32, discount_cents: u32) -> impl Fn(u32) -> u32 {
    move |amount_cents| {
        if amount_cents >= min_cents {
            discount_cents
        } else {
            0
        }
    }
}
```

Now we can generate custom promotion engines dynamically:
```rust
let flash_sale = make_percentage_discount(15);
println!("Discount on $100: ${:.2}", flash_sale(10000) as f64 / 100.0); // $15.00
```

## Why Every Closure Has a Unique Type

A subtle but crucial aspect of Rust: **every closure has its own unique, unnameable type generated by the compiler**.

Even if two closures have the exact same parameters and return type:
```rust
let f1 = |x: u32| x + 1;
let f2 = |x: u32| x + 2;

// COMPILE ERROR: mismatched types!
// let closures = [f1, f2];
```
Rust's compiler creates an anonymous struct for `f1` (e.g. `closure_1`) and a different anonymous struct for `f2` (e.g. `closure_2`).
Because arrays `[T; N]` require every element to have the exact same concrete type, `[f1, f2]` fails to compile!

To store heterogeneous closures in an array or collection, you can either:
1. Generate them from the same factory function (`make_percentage_discount`), or
2. Use function pointers `fn(u32) -> u32` (if they capture no environment), or
3. Use trait objects (`Box<dyn Fn>` or `&dyn Fn`).

## Common Compiler Errors & How to Fix Them

### 1. `error[E0507]: cannot move out of captured variable in Fn/FnMut closure`
**The Mistake**:
```rust
let name = String::from("VIP Voucher");
let consume_voucher = || {
    let owned = name; // COMPILE ERROR: cannot move out of `name` in an `Fn` closure!
};
```
**Why It Happens**:
Because `consume_voucher` might be called multiple times, moving `name` out on the first call would leave it uninitialized for subsequent calls.
**The Fix**:
Clone the value inside the closure if you need an owned copy, or use `FnOnce` if the closure is only ever executed once.

---

### 2. `error[E0382]: borrow of moved value`
**The Mistake**:
```rust
let threshold = 5000;
let promo = move |x| x >= threshold;
println!("{}", threshold); // COMPILE ERROR: threshold used after move!
```
**Why It Happens**:
The `move` keyword forces all captured variables to be moved. (Note: for Copy types like integers, a copy is moved; but for non-Copy types like `String`, the variable is consumed).
**The Fix**:
Only capture what is necessary, or clone non-Copy data before moving if you still need it in the outer scope:
```rust
let title = String::from("Voucher");
let title_clone = title.clone();
let promo = move || println!("{}", title_clone);
println!("Original title: {}", title); // OK!
```

## Idiomatic Rust Best Practices

1. **Prefer `Fn` Over `FnMut`, and `FnMut` Over `FnOnce`**: When writing functions that take closures, choose the least restrictive trait bound. Accepting `FnOnce` means you can only call the closure once; accepting `Fn` gives you the maximum flexibility.
2. **Use Factory Functions with `move` for Configurable Business Rules**: Encapsulate parameters in higher-order functions (`make_percentage_discount`) rather than passing dozens of arguments through function signatures.
3. **Keep Closures Small and Focused**: Closures are best when concise (1-5 lines). If a closure requires dozens of lines of complex logic, extract it into a standalone function or module method.
4. **Leverage Type Inference**: Avoid annotating closure parameter types unless the compiler explicitly demands disambiguation.
